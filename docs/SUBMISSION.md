## Output format (one JSON line per case, in `cases.jsonl` order)
```json
{"case_id": "...", "alert_ids": ["..."], "verdict": "CLOSE|RFI|ESCALATE", "reason_code": "...", "reason": "2-4 sentences", "evidence": ["IDs"]}
```
| Rule | Check |
|---|---|
| Exactly one line per case; a missing case counts as ESCALATE | `system/validate.py` |
| `alert_ids` = every alert in the case | `system/validate.py` |
| `reason_code` must belong to the verdict (26 codes, table in the brief) | `system/validate.py` |
| `reason`: 2 to 4 sentences naming the case's own facts and documents; an RFI says exactly what to ask for | `system/validate.py` (sentence count) |
| `evidence`: IDs exactly as in the files, and they must exist; the deciding ones should be included | `system/validate.py`, `tests/counterfactual_test.py` |

## How it is scored (for reference)
- Unseen cases 60% (verdicts 60 / reasons 40), development cases 20%, reproducibility 20% (same verdict and reason code in all 5 runs; it scales with the unseen score).
- Cost per case, where rows are the right verdict and columns are what was sent:

| right \ sent | CLOSE | RFI | ESCALATE |
|---|---|---|---|
| CLOSE | 0 | 3 | 3 |
| RFI | 10 | 0 | 2 |
| ESCALATE | 10 | 3 | 0 |

- Escalating everything scores 0.
